# Ассет-пайплайн Blender → Godot

## Статус

Скрипты написаны под **Blender 4.2+** и запускались только с заглушкой `bpy`:
Python-логика и данные проверены, вызовы Blender API — нет (в среде разработки
Blender был недоступен). Если какая-то операция `bpy.ops` в вашей версии
называется иначе, правка будет локальной: все вызовы API собраны в `bl_utils.py`.

## Запуск

```bash
# всё сразу (+ .blend-исходники для доработки художником)
blender -b -P code211/blender/build_assets.py -- --out code211/godot/assets/models --blend
# только выбранное
blender -b -P code211/blender/build_assets.py -- --out code211/godot/assets/models --only cop,pistol,shelf
# самопроверка спецификации без Blender
python3 code211/blender/spec.py
```

После генерации откройте проект в Godot (импорт произойдёт сам) или выполните
`godot --headless --import`.

## Что генерируется

| Файл | Содержимое | Контракт с игрой |
|---|---|---|
| `cop.glb`, `bandit_light.glb`, `bandit_medium.glb`, `bandit_heavy.glb`, `cashier.glb`, `customer.glb` | low-poly персонаж (≈ 30–45 коробок), узлы-шарниры `hips, spine, neck, shoulder_l/r, elbow_l/r, hip_l/r, knee_l/r`, 20 клипов | `CharacterRig` требует клипы `idle, walk, run, aim, shoot, reload, cover, hit, death`; остальные необязательны (есть запасные). Узел `Muzzle` — точка вылета пули. |
| `weapons/pistol.glb` | затвор, рамка, рукоять, магазин | узлы `Slide` и `Mag` (анимация затвора/магазина), `Muzzle` |
| `weapons/baton.glb` | дубинка | — |
| `props/<kind>.glb` | `shelf, shelf_wall, fridge, counter, crates, pallet, freezer, pillar, atm, display` | только внешний вид: коллизия и укрытия строятся по размерам из `LevelBuilder.PROPS`, поэтому ассет не может сломать геймплей |
| `police_car.glb` | кузов, мигалки, колёса | узел `DoorPivot` (поворот двери в ролике) |

Если файла нет или в нём не хватает обязательных узлов или клипов, игра пишет
предупреждение и использует встроенную процедурную модель.

## Оси и единицы

- 1 единица = 1 метр. Персонаж стоит в начале координат и смотрит в −Y (Blender), то есть в −Z (Godot).
- Перевод выполняет `bl_utils.g2b()`: точка `(x, y, z)` Godot → `(x, −z, y)` Blender.
- Повороты шарниров: `rotation_mode = 'YXZ'`, значения `(rx, −rz, ry)`. Тогда углы
  из `spec.py` совпадают с углами процедурных анимаций игры.
- Экспорт: glTF Binary, `+Y up`, анимации в режиме **NLA Tracks**. Каждый клип —
  NLA-трек с одинаковым именем на всех шарнирах; экспортёр собирает их в одну анимацию.

## Как дорабатывать модели художнику

1. Сгенерируйте `.blend` с флагом `--blend`.
2. Меняйте меши: детализируйте, добавляйте UV и текстуры. **Не переименовывайте**
   шарниры, `Muzzle`, `Slide`, `Mag`, `DoorPivot` и NLA-треки.
3. Для скиннинга можно заменить коробки на один меш с арматурой. Тогда кости должны
   называться так же, как шарниры, а клипы — так же, как треки.
4. Экспортируйте с теми же настройками (см. `bl_utils.export_glb`) в `godot/assets/models/`.

## Бюджет полигонов (рекомендации для iPhone)

| Тип | Сейчас | Потолок |
|---|---|---|
| Персонаж | ≈ 500 треугольников | 5–8 тыс. |
| Реквизит | 12–150 | 1–2 тыс. |
| Машина | ≈ 400 | 6 тыс. |
| Оружие в руках | ≈ 60 | 3 тыс. |

Не больше 2–3 материалов на модель. Текстуры 512–1024 px, Godot сожмёт их в ASTC
(`import_etc2_astc=true` уже включено).

## Проверка пути импорта без Blender

`godot --headless -s res://tools/export_reference_glb.gd -- /путь` экспортирует
процедурных персонажей в `.glb` через glTF-экспортёр Godot. Такой файл, положенный
в `assets/models/`, игра подхватывает (проверено: 20 клипов, анимации играют).
Его же удобно импортировать в Blender как эталон пропорций и поз.
